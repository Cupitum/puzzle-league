# Account deletion requests — trusted manual platform process only

A verified password + confirmed email are required in the Edge handler before the protected request register is written. League moderators and owners cannot see or administer the platform deletion table. Duplicate open requests are denied; users can view only their own current status. Nothing deletes an account on request.

**Monitoring:** a designated trusted Supabase platform administrator must inspect `app_private.account_deletion_requests` using their secured, audited operator console at least once per business day during the pilot. Export only `request ID`, pseudonymous account ID, `status` and timestamps to the private support register; send a notification through the organisation's already-approved secure administration channel. Do not send passwords, Auth tokens, user emails, raw shares or internal notes into league messages.

**Manual workflow:** verify request and legal identity using established support practice; identify leagues owned by that user and seek owner transfer/closure resolution; determine consequences for shares, audit, award integrity, retention and third-party data; obtain approved privacy/retention policy and documented administrator authorization before irreversible steps. The registered status may move to `under_review`, `awaiting_owner_resolution`, `completed`, `declined` or `cancelled` via `app_private.p7_admin_deletion_status` in a real trusted postgres/supabase_admin session. Do not mark `completed` unless an independently authorized real process has actually finished. This function changes only the request status and audit; it **does not delete** an Auth user, profile or other data.

No deletion/erasure SQL is part of this package. A full policy and actual deletion procedure require separate authorized administrative change control, not testing. Preserve immutability of submitted shares, ledger events and retained audits where lawful. The status register is not a substitute for Privacy Office review.
